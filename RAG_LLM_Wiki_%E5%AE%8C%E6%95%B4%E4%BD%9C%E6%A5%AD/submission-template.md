# 繳交文字範本（請先填入自己資料與實測網址）

**標題**：［學校簡稱］ ［學號］ ［系級］ ［姓名］ RAG LLM Wiki 教學簡報

**1. LLM Wiki 主題與介紹**  
我選擇「RAG 是什麼？讓 AI 學會先查資料再回答」。這份 Wiki 以初學者為主要對象，整理 RAG 的原理、資料切塊、向量化、檢索、生成與常見限制。

**2. LLM Wiki 成果連結**  
［填入已成功開啟的 GitHub Pages Wiki 網址］。我整理了 Lewis 等人原始研究論文、IBM、AWS、Microsoft Learn、Google Cloud 共五份資料。每份來源以 LLM 輔助改寫成摘要，建立概念頁與來源映射。

**3. 教學 HTML 簡報連結**  
［填入已成功開啟的 slides.html 網址］。共有 12 頁，包括生活化比喻、流程拆解、常見誤會、錯誤檢查與小測驗。

**4. Loop / Graph 流程**  
確定學習目標 → 查找 5 份資料 → 摘要並核對來源 → 建立可連結的 Wiki → 查詢 Wiki → 檢查對應來源 → 生成 HTML 簡報 → 測試與修正。若來源不符，回到摘要；若 Wiki 連結錯誤，回到建庫；若簡報顯示或操作錯誤，回到生成階段。詳見 `workflow.md`。

**5. 一次實際執行與檢查結果**  
本地靜態測試通過（5 份來源、10 個概念、12 頁簡報），本地 Chromium 測試完成 Wiki 搜尋、開啟來源、翻頁、鍵盤切換、第 11 頁測驗與手機版。實測截圖放在 `screenshots/`，詳細紀錄見 `check-log.md`。［請補上自己瀏覽 GitHub Pages 的結果或線上截圖］。

**6. 反思**  
本次初版實際發現的問題是在「HTML 簡報互動」節點：按完下一頁之後，鍵盤右方向鍵沒有翻頁。調整快捷鍵的事件條件後重新測試，已能從第 2 頁進到第 3 頁。之後我把基本互動測試往前移到 HTML 功能完成當下，而不是等美化後才檢查。另外，在產生簡報前，我也先檢查來源 ID／概念映射，並讓 Wiki 與簡報共用 `wiki-data.js`，避免內容版本不一致。
